# Bin

This directory contains executable scripts. Most of the scripts here come from Ruby gems installed by `bundle install`
and shouldn't be edited. Others are custom scripts created for this project.

## Project Scripts

These scripts are specific to this project.

| Script | Description |
|--------|-------------|
| `build-docker-image` | Build a Docker image from the current Git commit. |
| `build-watch` | Filter a Docker build log down to step starts, finishes, cache hits and errors. |
| `chanbooru-deploy` | Fork: bring a host up to a commit -- check the image directory, rebuild the image only when a runtime file changed, install and activate the release, recreate the containers, verify the running revision and the front page. Refuses a commit that has not passed the deploy gate: origin must hold the annotated tag `deploy-gate/<commit>`, which `coherence gate --repo chanbooru --deploy` pushes on a PASS. `--rollback` goes back one release, ungated: every release it can return to was already deployed. |
| `chanbooru-release` | Fork: install, activate, list and prune releases (one commit's app tree, compiled assets and bootsnap cache) under `/srv/danbooru`. |
| `chanbooru-reset-password` | Fork: reset one account's booru password from the server -- and, with `--matrix <user>`, that person's Matrix (MAS) password too; prints one one-time link that shows the new passwords once on the site, never a password itself (`PasswordReveal`). Exits 3 when MAS refuses: the booru reset stands and the link shows that password alone. mas-cli takes the Matrix password as an argument, so while it runs it is visible to root (docker events) and to local users in /proc; the person changes it on first use. |
| `chanbooru-storage` | Fork: install (once) and check (every deploy) the host image directory on the storage drive. |
| `danbooru-dev-entrypoint` | Entrypoint for containers started with `bin/dev` / `docker-compose.dev.yaml`. |
| `dev` | Shortcut for `docker compose -f docker-compose.dev.yaml`. |
| `devcontainer-entrypoint` | Entrypoint for the devcontainer. |
| `find-untested-urls` | Find commented URLs in `app/logical/source/url/` that have no parser test coverage. |
| `generate-changelog` | Generate a changelog from Git commits between two refs. |
| `github-print-test-results` | Parse JUnit test output and print GitHub workflow annotations and a summary. |
| `media-conv` | Convert media files using Danbooru's media conversion logic. |
| `landing-cpu` | Fork: measure where the landing page's CPU goes in a headless browser. |
| `landing-preview` | Fork: render the landing carousel with live data and the working tree's code. |
| `media-ls` | List properties of media files (like `ls`, but using Danbooru's media file logic). |
| `permission-matrix` | Fork: print who can do what, per level, across every policy. |
| `postview-shift` | Fork: measure whether the post view holds still while the next post loads. |
| `setup` | Upstream's: installs Docker and Git and clones UPSTREAM Danbooru. It does not install this fork; see "Installing it somewhere else" in the top-level README. |
| `test-sources` | Run all of a specific site's parsing & extractor tests. |
| `update` | Update Ruby gems and npm packages and run pending migrations. |

## Bundler Scripts

These scripts are generated by Ruby gems via `bundle install` and should not be edited manually.

| Script | Description |
|--------|-------------|
| `bundle` | Run Bundler (gem dependency manager). |
| `cdtext` | Run the `cdtext` binary. |
| `dotenv` | Run the `dotenv` binary. |
| `dtext` | Run the DText parser CLI. |
| `good_job` | Run the GoodJob background job processor. |
| `heapy` | Run the Heapy memory profiler CLI. |
| `puma` | Run the Puma web server. |
| `pumactl` | Control a running Puma process. |
| `rackup` | Start a Rack-compatible web server. |
| `rails` | Run Rails CLI commands (console, server, generate, etc). |
| `rake` | Run Rake tasks. |
| `rbtrace` | Trace method calls in a running Ruby process. |
| `rdbg` | Run the Ruby debugger. |
| `rubocop` | Run the Ruby linter. |
| `shakapacker` | Run the Shakapacker webpack CLI. |
| `shakapacker-dev-server` | Start the Shakapacker webpack dev server with hot reload. |
